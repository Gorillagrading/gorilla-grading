# GORILLA GRADING — GREENFIELD PROTOTYPE PACK

## Objetivo

Este proyecto NO parte de un repositorio existente.

El CEO ha mostrado un ejemplo visual/conceptual de cómo imagina Gorilla Grading, pero ese ejemplo es una referencia y NO debe tratarse como código fuente, arquitectura existente ni producto aprobado.

El objetivo de esta carpeta es servir como contexto para crear desde cero varios modelos/prototipos de Gorilla Grading con Antigravity + Gemini, compararlos y presentar opciones al CEO antes de decidir qué dirección construir.

## Material de origen

- Investigación y estrategia de Marketing entregada por el equipo.
- PDF de especificación visual de la web.
- Logos proporcionados.

## Principio de trabajo

Primero se prototipa. Después se decide. Luego se construye.

No asumir que ninguna pantalla del ejemplo del CEO está técnicamente implementada.
No asumir que ninguna funcionalidad del ejemplo existe realmente.
No convertir afirmaciones de investigación en hechos no verificados sin marcarlas como hipótesis.

## Estructura

- 00_MASTER_CONTEXT.md — contexto maestro.
- 01_MARKET_RESEARCH.md — síntesis del estudio recibido.
- 02_COMPETITIVE_ANALYSIS.md — lectura competitiva y gaps a explorar.
- 03_PRODUCT_STRATEGY.md — concepto de producto y prioridades.
- 04_BRAND_SYSTEM.md — branding recibido y reglas de uso.
- 05_UX_UI_SYSTEM.md — sistema UX/UI para prototipos.
- 06_TECHNICAL_ARCHITECTURE.md — arquitectura propuesta desde cero.
- 07_AI_STRATEGY.md — estrategia de IA.
- 08_COMPUTER_VISION.md — concepto de Computer Vision/grading asistido.
- 09_FEATURES_AND_ROADMAP.md — MVP y evolución.
- 10_PROTOTYPE_MODELS.md — tres direcciones de diseño para presentar al CEO.
- 11_ANTIGRAVITY_PROMPTS.md — prompts listos para construir los prototipos.
- 12_DECISION_LOG.md — decisiones, hipótesis y validaciones pendientes.

## Regla de oro para Antigravity

Construir prototipos independientes y comparables. No crear una arquitectura gigantesca antes de validar UX, contenido y dirección visual.
